# Network Infrastructure

При проектировании сети я хотел разделить доменную инфраструктуру, серверы, веб-сервисы и машину для проведения атак. Это позволяет моделировать разные сценарии взаимодействия между сегментами и контролировать сетевой трафик.
## Общая схема

В качестве центрального сетевого устройства я использую **OPNsense**. Она выполняет роль маршрутизатора и межсетевого экрана, через который организовано взаимодействие между сегментами лаборатории.

Для разделения инфраструктуры я создал четыре виртуальные сети:

|Сегмент|Подсеть|Шлюз|Назначение|
|---|---|---|---|
|LAN|`10.10.10.0/24`|`10.10.10.1`|Доменная инфраструктура и клиентские машины|
|SERVER|`10.10.20.0/24`|`10.10.20.1`|Серверы и системы мониторинга|
|DMZ|`10.10.30.0/24`|`10.10.30.1`|Веб-сервисы и уязвимые приложения|
|ATTACK|`10.10.40.0/24`|`10.10.40.1`|Машина для проведения тестовых атак|

## Сегменты сети

### LAN - доменная инфраструктура

В этом сегменте находятся основные Windows-машины.

|Устройство|IP-адрес|Назначение|
|---|---|---|
|DC01|`10.10.10.10`|Windows Server 2022, Active Directory и DNS|
|Windows 11|DHCP / назначенный адрес|Клиент домена `lab.local`|


### SERVER - серверная инфраструктура

В этом сегменте размещаю серверы, которые обеспечивают работу лаборатории и мониторинг событий.

|Устройство|IP-адрес|Назначение|
|---|---|---|
|WAZUH01|`10.10.20.10`|Ubuntu Server 24.04.5, Wazuh All-in-One|

WAZUH01 принимает события от подключённых агентов, анализирует их и отображает результаты в Dashboard.

DC01 передаёт события на WAZUH01 через Wazuh Agent.

### DMZ - зона веб-сервисов

Этот сегмент предназначен для размещения сервисов, которые потенциально могут быть доступны из других сетевых зон.

Здесь планирую разместить отдельную Ubuntu Server с DVWA. Это позволит проводить эксперименты с веб-уязвимостями, наблюдать за сетевой активностью и анализировать события на стороне сервера.

### ATTACK - атакующий сегмент

В этом сегменте находится Kali Linux.

Я использую её как отдельную машину для проведения контролируемых атак на другие компоненты лаборатории. Такое разделение позволяет не смешивать атакующую инфраструктуру с доменными и серверными системами.

## Роль OPNsense

OPNsense связывает все четыре сегмента и обеспечивает маршрутизацию между ними.

Для меня важно, что сетевые зоны не объединены в одну общую сеть. Между ними можно задавать отдельные правила фильтрации и контролировать, какие устройства могут взаимодействовать друг с другом.

Это особенно важно при моделировании атак: я могу проверять не только действия непосредственно на целевой машине, но и то, как сетевая сегментация влияет на возможности атакующего.

## Логика взаимодействия

В лаборатории предусмотрены следующие основные направления взаимодействия:

- LAN → SERVER: передача событий безопасности от Windows-машин к Wazuh.
    
- ATTACK → LAN: тестирование атак на доменную инфраструктуру.
    
- ATTACK → DMZ: тестирование веб-приложений и сервисов.
    
- Межсегментное взаимодействие: контролируется правилами OPNsense.
    

Это описание логических направлений, а не утверждение, что весь такой трафик без ограничений разрешён. Фактический доступ определяется настройками межсетевого экрана.

## Зачем нужна сегментация

Я разделил сеть не только ради порядка. Каждый сегмент представляет отдельную зону с собственной ролью и уровнем доверия.

Такой подход позволяет:

- Изолировать атакующую машину от остальной инфраструктуры.
    
- Отдельно размещать серверы и веб-приложения.
    
- Контролировать доступ к доменному контроллеру.
    
- Анализировать сетевые взаимодействия между разными зонами.
    
- Проверять эффективность правил межсетевого экрана.
    

В дальнейшем я планирую расширять набор сценариев и использовать сетевую сегментацию для проверки не только обнаружения атак, но и эффективности защитных мер.

## Текущий статус
